# BTC International Participation Tracker

A live, multi-season dashboard tracking every international horse, trainer, and winning ride at the **Bahrain Turf Club** — from the inaugural Bahrain International Trophy raids in 2019/20 through to the present.

The dashboard is a single static HTML page that reads a JSON file generated from a master Excel workbook. Edit the workbook, regenerate the JSON, push to GitHub — and your live site updates.

---

## Quick start

```bash
# 1. Clone
git clone <your-repo-url>
cd btc-international-tracker

# 2. (Optional) regenerate the data from the source XLSX
pip install -r requirements.txt
python scripts/build.py

# 3. Preview locally — DO NOT just double-click index.html,
#    browsers block fetch() on file:// URLs
python3 -m http.server 8000
# open http://localhost:8000
```

That's it. The dashboard loads `data/seasons.json` and renders 7+ seasons of horse-by-horse, race-by-race detail.

## Updating the data

The **source of truth** is `data/tracker.xlsx`. It has one sheet per season (`2019-20`, `2020-21`, … `2025-26`), each laid out in five sections:

| Section | What it holds |
|---|---|
| 1 — Horses by Competition | Country totals per competition (BIT, BTS, etc.) |
| 2 — Horse Register | Every international runner, with trainer, country, comp, win count |
| 3 — Winners | Each individual race won, with date and trainer |
| 4 — Trainers | International trainer list, grouped by competition |
| 5 — Additional Races | HH Shaikh Nasser, Crown Prince, King's Cup detail |

### Workflow

1. **Open `data/tracker.xlsx`** in Excel or LibreOffice.
2. **Edit** the relevant season sheet — add new horses, mark winners, log race results.
3. **Save** the file.
4. **Run** `python scripts/build.py` to regenerate `data/seasons.json`.
5. **Commit & push** both files. The dashboard updates on the next page load.

> The build script is forgiving — trailing whitespace, common typos (`"Baharain Turs Series"`), and varied country spellings (`Qatar` / `QTR` / `QAT`) are all normalised.

### Skip the build step (with GitHub Actions)

If you set up the included Pages workflow (see below), you can skip the manual build step entirely — just commit changes to the XLSX and the Action will rebuild and deploy the JSON for you.

## Deploying to GitHub Pages

This repo is pre-configured for Pages deployment via GitHub Actions. Once enabled, every push to `main` automatically rebuilds the JSON and publishes the site.

### One-time setup

1. Push the repo to GitHub.
2. Go to **Settings → Pages**.
3. Under **Build and deployment → Source**, choose **GitHub Actions**.
4. Done. The first deploy runs immediately.

Your dashboard will be live at: `https://<your-username>.github.io/<repo-name>/`

After this, the loop is simply: **edit XLSX → commit → push → site updates**.

### Alternative: branch-served Pages

If you prefer the simpler "serve from branch" mode:

1. Run `python scripts/build.py` locally before each commit.
2. In **Settings → Pages**, choose **Deploy from a branch** → `main` / `/` (root).
3. You'll need to commit both `tracker.xlsx` and `seasons.json` together each time.

## How the dashboard works

- `index.html` is a fully self-contained static page (no build step, no bundler).
- On load, it does `fetch('./data/seasons.json')`, then renders everything client-side.
- Fonts come from Google Fonts (Fraunces + Manrope) and charts from Chart.js — both via CDN, so no `node_modules` needed.
- The brand palette is keyed off **`#980B2C`** (the official BTC crimson) with ivory and champagne-gold accents.

### Two views

- **All Seasons** — cross-season trends, all-time trainer leaderboard, top multi-season campaigners.
- **Per Season** — KPI strip, country donut, competition breakdown, trainer leaderboard, winner timeline, filterable register, and premier race results.

Seasons before 2025/26 are marked with a "pending verification" notice (per the workbook's own note); the team can clear that flag in `index.html` (look for `VERIFIED_SEASONS`) once data has been checked against racing-office archives.

## Updating the dashboard itself

To change colours, copy, layout, or add new visualisations: edit `index.html` directly. The structure is:

- **Top of file** — CSS variables (colours, spacing). Almost all visual tweaks live here.
- **`<body>`** — masthead, hero, season-rail container, content container, footer.
- **`<script>` at the bottom** — data loader, tab logic, and the two renderers: `renderOverview()` and `renderSeason()`. Each section in `renderSeason` is a discrete block you can comment out, rearrange, or extend.
